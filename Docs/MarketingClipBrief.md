# Blackbird marketing clip options

Prepared: 2026-09-09. Recording belongs to the user; detailed documentation examples belong to the other agent.

Aim for one visible benefit per clip, roughly 8–20 seconds. Show the action and its result, using a configured demo project. These are options: start with three strong clips rather than recording everything.

| Priority | Clip | What to show | Suggested on-screen message |
| --- | --- | --- | --- |
| First | One workflow from build to device | Run a prepared workflow, briefly show its stages, then the game running on a device. Cut across long build waits. | Build. Deploy. Play. |
| First | Repeat a task without rebuilding the setup | Choose a saved action configuration and run it again; finish on clear success/output. | Set it up once. Run it again. |
| First | Find the output you need | Finish a run, open its history/logs, and reveal the useful output immediately. | Less searching. More fixing. |
| Next | Switch projects without switching tools | Change active project and run a project-aware action with the matching configuration. | Your projects. One workspace. |
| Next | From finished build to storefront upload | Select a prepared build and destination, start the upload, then show completion using a safe test destination. | A shorter path to publishing. |
| Next | Your own script with an approachable interface | Show a finished custom action's inputs and run button, followed by its result. Skip the authoring tutorial. | Keep your scripts. Make them easier to use. |
| Optional | Everyday device tasks together | Select a device, launch an app, retrieve logs, and show the result. | Device work without the tool shuffle. |
| Optional | One workspace across engines | Brief cuts between configured Unreal, Unity, and Godot actions that work in the released build. | Different engines. A familiar workflow. |

## Placement

- Homepage: one strong build-to-device clip or a brief montage of the first three benefits.
- Blackbird page: individual clips paired with the benefit they demonstrate, replacing the repeated long video.
- Game-development feature area: device or storefront examples, where available.
- Social posts: reuse a single benefit with a short caption and product link.

## Recording guidance

- Use a clean demo project with readable names, consistent theme, and enlarged UI. Keep the pointer deliberate.
- Capture a high-quality source video; decide GIF versus compressed video during web export. Short silent loops need no narration, and video may be much smaller than GIF for this UI.
- Make the result visible. Avoid clips that spend their entire duration in settings or waiting for a build.
- Trim or visibly jump across waits; do not imply a full game build takes seconds. Make no speed multiplier claims without measurements.
- Use concise text that works with sound off. Leave a brief settled frame at the start and end for a clean loop.
- Remove tokens, account details, private paths, unreleased game content, and sensitive output. Use approved demo material and test upload destinations.
- Only show functionality working in the public build. If an integration isn't ready, choose another clip rather than implying availability.
