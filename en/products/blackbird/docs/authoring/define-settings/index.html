Documentation / Create your own Actions

Define settings for an Action

Choose identities, types, scopes, and validation deliberately.

Based on Blackbird 0.8.4-alpha.1. Updated 2026-10-08. Some features may differ from your installed version.

Add or reuse a setting

In New Action or Edit Action, open Custom Settings. Use Add Category and Add Container to organize inputs. Add Setting creates a definition in your bundle's shared library; Reuse Setting references an existing definition without copying it.

For the tutorial, use namespace example, key outputDirectory, label Output directory, type Folder, and scope Project. The resulting ID is example.outputDirectory. Enable Required in this Action's usage. Use that full ID in scripts and conditions.

Choose scope and constraints

Project values belong to the selected project. Application values belong to this Blackbird installation. Run values apply to one execution; non-secret suggestions may be remembered, but secrets are not. Device-scoped persistence is not supported.

Choose Text, Integer, Number, Boolean, Choice, File, Folder, Secret, or Array to match the input. Set path constraints where needed. Secrets must have no default. Keep descriptions useful and concise; Markdown links can point to tool downloads or setup instructions.

Definition and usage

This definition belongs in the shared library's declared definition file, alongside its category declaration: ``json { "id": "example.outputDirectory", "revision": 1, "label": "Output directory", "type": "folder", "scope": "project", "category": "example.settings", "order": 10 } ` The Action references it through settings.inputs: `json { "definition": "example.outputDirectory", "owner": "example-settings", "revision": 1, "required": true } `` The Action also declares example-settings as a dependency and requires its advertised interface. These are fragments; the downloadable tutorial includes complete packages.

Order and maintain fields

Set explicit orders in the owning definitions: controlling choices first, related inputs together, advanced groups last. Engine settings put Project before Build profiles. Category dropdowns remain alphabetical. Requiredness, profile membership, and conditions belong to the Action usage.

Keep established IDs stable. Display-only edits retain the revision; value-contract edits advance it and require reviewed consumer references. Save through the editor and test missing, valid, and invalid values before sharing.
