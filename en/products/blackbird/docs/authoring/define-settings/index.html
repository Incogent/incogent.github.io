Define settings for an Action

Choose identities, types, scopes, and validation deliberately.

Based on 0.8.3-alpha.4 development documentation. Updated 2026-09-22. Some features may differ from your installed version.

Add a setting

In New Action or Edit Action, open Custom Settings and add a field. Choose This Action for a private input or select/create a shared namespace. Choose an existing shared key when you mean to reuse a definition; otherwise create a new key.

For the tutorial, use namespace example, key outputDirectory, label Output directory, type Folder, scope Project, and Required. The resulting identity is example.outputDirectory. Use that full ID in scripts and conditions.

Choose scope

  • Project: values belonging to the selected project, such as an app ID or output folder.
  • Application: a tool or preference shared across this installation.
  • Run: a choice confirmed for the current execution. Remembered non-secret values may prefill the next prompt; secrets are never remembered as run suggestions.

Device-scoped persistence is not supported. If an input depends on a selected device, read the device context or request an appropriate run input rather than inventing a device scope.

Choose type and constraints

Text, Integer, Number, Boolean, Choice, File, Folder, Secret, and Array represent different values. Use Choice for a defined set, and file/folder controls for paths. Set allowed extensions or existence requirements where appropriate. Give a useful label and description rather than exposing an internal ID as the only instruction.

Required fields must be supplied when applicable. A default is a fallback, not a value copied into every existing project. Secret fields must not contain a default. Avoid a secret value in a placeholder, description, or script source.

What the manifest means

{
  "id": "example.outputDirectory",
  "label": "Output directory",
  "type": "folder",
  "scope": "project",
  "required": true
}

This is one entry in the manifest's parameters array, not a complete package. Save through the editor and validate the Action. Test a missing value, a valid value, and an invalid path before sharing it.

Do not rename an established ID casually: saved settings, conditions, Workflows, and scripts refer to it. A new label can improve wording without changing the identity.
