Read inputs and execution context

Use the runtime instead of reading configuration files yourself.

Based on 0.8.3-alpha.4 development documentation. Updated 2026-09-22. Some features may differ from your installed version.

Initialize the PowerShell runtime

Every PowerShell Action should begin with the runtime import and fallback trap: ``powershell Import-Module (Join-Path $env:BLACKBIRD_RUNTIME_ROOT 'Blackbird.Runtime.psm1') -Force trap { Set-BlackbirdUnhandledFailureResult -ErrorRecord $_; break } `` Blackbird supplies this runtime. Do not add a package dependency solely to read settings or obtain the selected project/device.

Read declared parameters

$Folder = Get-BlackbirdParameter -Name 'example.outputDirectory' -Required
$OptionalLabel = Get-BlackbirdParameter -Name 'example.label'

The parameter's declared type determines the resolved value. Arrays contain records; booleans are not strings such as "yes"; numbers should not be compared as text. Treat missing optional values explicitly. -Required identifies an absent runtime parameter; manifest validation and your domain checks still determine whether a present value is usable.

Read context when needed

$Project = Get-BlackbirdProject -Required
$Device = Get-BlackbirdDevice -Required
$Serial = Get-BlackbirdDeviceSerial -Required
$Context = Get-BlackbirdContext

Only require a device/project when the Action actually needs it, and declare that requirement in the Action editor. Use the context supplied to this run; do not rediscover the top-window selection by reading settings from disk.

Paths and generic variables

Use $env:BLACKBIRD_PACKAGE_ROOT or $PSScriptRoot for files shipped beside the script. Use declared file/folder parameters for user-selected paths. Avoid assuming the process working directory is the game project.

Get-BlackbirdVariable -Name 'BuildFlavor' reads a generic string variable from the effective variable dictionary. It does not read parameters. Project generic variables override same-named global generic variables. For new user-editable inputs, prefer typed Action parameters.

Other runners

PowerShell helpers are not Bash commands. Other runners use the normalized JSON at BLACKBIRD_CONTEXT_PATH and their supported runtime/template. The context and result paths are temporary per-run files, not persistent storage. Do not override reserved BLACKBIRD_ environment variables or retain context files containing resolved secrets.
