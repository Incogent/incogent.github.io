Share settings across Actions

Configure one project fact and reuse it from multiple Actions.

Based on 0.8.3-alpha.4 development documentation. Updated 2026-09-22. Some features may differ from your installed version.

Reuse the same definition

Two Actions share a setting by declaring the same canonical ID with a compatible definition. Matching labels alone do not share values. example.outputDirectory and example.outputFolder are different settings even if both controls say Output directory.

Reuse the shared key through the editor so scope, type, value mode, choices, and path constraints agree. Bundled definitions take precedence when determining the editor for a shared built-in identity; a custom Action should not redefine their contract to mean something else.

Try two Actions

  1. Complete Report Output Directory from the first-Action authoring guide.
  2. Create Count Output Files, ID count-output-files, requiring a project and no device.
  3. Add the existing shared example.outputDirectory setting through the editor. Keep the same Folder/Project/Required definition.
  4. Use the following run.ps1 and reload Actions.
  5. Configure Output directory once for ExampleProject, then run both Actions.
  6. Change that project setting to another existing folder and run both again. The first reports the new path; the second counts files there.
Import-Module (Join-Path $env:BLACKBIRD_RUNTIME_ROOT 'Blackbird.Runtime.psm1') -Force
trap { Set-BlackbirdUnhandledFailureResult -ErrorRecord $_; break }

$OutputDirectory = Get-BlackbirdParameter -Name 'example.outputDirectory' -Required
$Files = @(Get-ChildItem -LiteralPath $OutputDirectory -File -ErrorAction Stop)
Set-BlackbirdSuccessResult -Title 'Output files' -Message ('Found {0} top-level files.' -f $Files.Count) -Items @($OutputDirectory)

The complete examples include both manifests and scripts. They read folders; they do not write output or modify saved settings.

Boundaries to remember

  • Changing the selected project selects that project's value; it does not overwrite another project's configuration.
  • A run-scoped setting is resolved for that execution, even when another Action uses the same ID.
  • Queued items and Workflows keep captured configuration. Edit them to intentionally adopt changed values.
  • A local assignment such as $OutputDirectory = 'C:\Example' changes only that process's variable.
  • If unrelated Actions should share a fact, keep it as a shared setting outside an Action-specific profile.

Resolve a conflict

If Blackbird reports incompatible definitions, compare the full ID and constraints. Match the existing definition when you intend to share. Choose a different namespace/key when the new input has a different meaning. Do not hide the warning by weakening the original Action's requirements.
