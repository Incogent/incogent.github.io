Documentation / Packages and customization

Choose or move the package library

Keep installed packages and local content in the intended folder.

Based on 0.8.3-alpha.4 development documentation. Updated 2026-09-22. Some features may differ from your installed version.

Find the active location

Open Settings > Packages and read Package library location. The library contains installed bundles and project configuration. Logs and temporary/cache data are stored separately; moving the library does not mean every Blackbird file moves with it.

Change Location versus Move Library

Change Location... selects the library to use after restart. It does not copy your current library into that folder. Use it to switch to a different library intentionally.

Move Library relocates the current library. Choose a writable, empty destination separate from the source, and review the confirmation. Do not select a parent/child folder or expect two existing libraries to merge. Let active work finish and close external editors or applications using files there before moving.

Local package folders

Custom packages created through the app are stored in My Actions. The layout is Bundles/user.actions/<package-id>/, with the package manifest and script together. Use the Action editor for manifest changes; edit its script in your preferred editor and reload Actions afterward.

Official and local bundles each have their own folder beneath Bundles. Internal configuration files are managed by Blackbird. A directory being visible does not mean it is safe to rename or remove while the app or an Action is using it.

Backups and old Actions

Use reviewed profile exports for portable configuration and custom Actions. Keep a separate backup before reorganizing files. Old flat Packages content is not automatically executable in the new bundle library; import custom Actions through the supported flow instead of copying official packages into My Actions.
