Documentation / Upload provider setup

Use a Custom CLI uploader

Connect a command-line uploader with explicit arguments and result rules.

Based on 0.8.3-alpha.4 development documentation. Updated 2026-09-22. Some features may differ from your installed version.

Prepare the command

Use this adapter when a supported command-line program can upload your artifact but has no dedicated Blackbird provider. Obtain it from its vendor, authenticate through its supported process, and first understand its command-line contract. Blackbird cannot infer the correct flags or upload policy for an arbitrary tool.

Configure the profile

  1. Select Custom CLI as the Uploader.
  2. Choose CLI tool and Working directory.
  3. Set Build or upload descriptor, Application ID, and Channel when your tool uses them.
  4. Add each argument using the argument editor. Keep a path with spaces as one argument; do not construct an extra shell command string to work around quoting.
  5. Configure environment variables needed by the tool and use the available secret handling for credentials.
  6. Set Success exit codes and, if needed, Required success output and Failure output patterns according to the tool's documented behavior.
  7. Run Validate without uploading, then test a real upload to a non-production destination.

Be precise about success

A process returning zero is not always proof that the intended remote operation happened. Conversely, informational text on standard error is not necessarily a failure. Configure the contract to match the tool, then verify the remote artifact manually during setup.

Validation-only checks Blackbird's local preparation; it is not a universal vendor dry-run switch. If the vendor offers a dry-run argument, deliberately configure and review it. Avoid patterns so broad that an unrelated message can be interpreted as success.

Diagnose a failure

Use the same executable version and working directory when reproducing a command outside Blackbird. Check argument boundaries, missing environment values, expiration of authentication, and output patterns. Never paste a credential-bearing command into feedback or public chat.
