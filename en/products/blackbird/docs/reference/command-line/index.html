Run Actions from the command line

Launch existing Actions and Workflows using the installed app.

Based on Blackbird 0.8.4-alpha.1. Updated 2026-10-08. Some features may differ from your installed version.

Connect to Blackbird

Use the installed Blackbird.exe's full path. Open Blackbird and let startup finish before sending commands. Commands contact that running app; they do not launch a separate runner or activate its window. --help works while the app is closed. --json selects machine-readable output; the old --cli prefix is unsupported.

& 'C:\Path\To\Blackbird\Blackbird.exe' --list-actions --search build --json
& 'C:\Path\To\Blackbird\Blackbird.exe' --describe-action update-project-version --project ExampleProject --json
& 'C:\Path\To\Blackbird\Blackbird.exe' --run-action system-information --json
& 'C:\Path\To\Blackbird\Blackbird.exe' --run-workflow 'Verify Project' --json
& 'C:\Path\To\Blackbird\Blackbird.exe' --run-queue --json

Actions and Workflows accept IDs or unique exact names. Projects use exact names; devices accept names or serials. Prefer stable IDs in scripts.

Discover and supply inputs

Use --list-actions, --list-workflows, --list-projects, and --list-devices to discover targets. --list-devices does not scan; --scan-devices requests discovery. --describe-action exposes inputs, choices, conditions, profile IDs, and profile inputKey values without revealing stored secrets.

Run inputs are a JSON object of canonical IDs with string values. Encode arrays as JSON text inside those strings. Pass the object using --parameters-stdin; send secrets through standard input, never command arguments. Configure persistent settings in Blackbird. Standalone command Actions and copied Queues cannot answer interactive prompts.

Queue behavior

--run-queue starts or resumes the actual Queue without a target. --run-workflow loads the saved Workflow into the actual Queue and runs it, replacing the current Queue. Save unsaved work first. --run-queue --copy explicitly runs a separate copy of pending items and preserves the editable Queue. Standalone Actions also preserve the Queue and selected project/device.

--queue reports current items and state. --pause-queue pauses after the current Action, --resume-queue resumes, and --stop-queue stops it. Workflows retain their saved projects and explicit devices; a --device override supplies the target for Current device items.

Track results and retry safely

Submission returns a run ID. Use --status, --wait <run-id> --timeout <seconds>, or --cancel <run-id>. A timeout ends only the wait, not the work. Acceptance is not completion: inspect the returned run state and failure guidance.

Changing commands emit a request ID. If a response is lost, retry the same request with --request-id and identical inputs. IDs and retained results last only for the app session; do not blindly retry after a restart. Exit codes are 0 for accepted/pending/success, 1 for execution failure, 2 for invalid input/configuration, 3 for unavailable devices, 4 for licensing, 5 for cancellation, and 6 for connection/internal errors.

The installed Skills/blackbird/SKILL.md provides agent usage instructions. For recurring work, create a Schedule in Blackbird instead of reproducing its internal scheduler arguments.
