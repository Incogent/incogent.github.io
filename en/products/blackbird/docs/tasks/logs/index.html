Collect project and device logs

Save the log relevant to the failed operation.

Based on 0.8.3-alpha.4 development documentation. Updated 2026-09-22. Some features may differ from your installed version.

Choose the source

Use the installed log Action for the system that failed, such as Pull Android App Logs, Record Android Device Logs, or Pull Steam Logs. Existing app logs and a live device recording answer different questions: a recording captures events while you reproduce the issue.

Collect

  1. Select the correct project and verified device when the Action needs them.
  2. Configure its app identity and output location. Choose only the relevant engine/device support when requested.
  3. Run the log Action and follow its recording/stop instructions if it is a live capture.
  4. Reproduce the problem while recording, if applicable.
  5. Use the completion window to find the saved files, then inspect them before sharing.

If no files are found, confirm that the app ran on that target and that its identity matches the configured value. An empty collection is different from a failed device connection. For Blackbird's own execution log, use the original Action's History entry instead of a device-log Action.

Share only what is needed

Logs can contain names, paths, server addresses, or application data. Keep the original privately, and supply the relevant excerpt or reviewed attachment with the time and reproduction steps. Do not include credentials or unrelated device logs.

Image and video brief

Screenshots: a log Action configuration and successful result with Open Folder. Use a synthetic short log excerpt. For live recording, a 10-second MP4 should show start, deliberate reproduction, stop, and result; do not film unrelated applications.
