Update a project version

Choose each version component and optionally include a VCS revision.

Based on 0.8.3-alpha.4 development documentation. Updated 2026-09-22. Some features may differ from your installed version.

Configure the format

In Project Settings, configure Version format as an ordered list. Available sources include Major, Minor, Patch, Build counter, Calendar date, and Version control revision. A source can appear once. Components are joined with periods; these custom formats are not necessarily Semantic Versioning.

Examples include Major.Minor.Patch and Major.Minor.Patch.Version control revision. Android numeric build codes remain separate. Ensure your distribution platform accepts the resulting format.

Run the update

  1. Select the project and engine for Update Project Version.
  2. Review the ordered format and Calendar date format if used.
  3. Choose the counter operation, such as incrementing a named counter or Last counter. Reset following counters affects counters to its right, not date/revision components.
  4. Use Refresh generated components to refresh date/revision without incrementing counters, or Set explicitly to seed a complete version in the configured order.
  5. Run and inspect the reported old/new value and engine files.

After reordering components, use Set explicitly to establish the intended counter positions. Old version-scheme settings are not converted automatically; update saved Workflows and queued items that use them.

Version control

Install Version Control support when available and configure the project's VCS. Git uses local HEAD (an abbreviated hexadecimal commit ID), Perforce uses the highest submitted changelist represented by synced files under the folder, and Unity Version Control uses the loaded changeset of a full workspace. Configure and authenticate the installed git, p4, or cm client separately. Blackbird does not provide checkout, sync, or commit operations.

Git does not require a particular hosting service or remote. Local changes and linked repositories are not fully described by one revision ID. Perforce's number does not prove a consistent workspace snapshot; partial UVCS workspaces without one loaded changeset are rejected. A failed revision lookup stops the version change.
