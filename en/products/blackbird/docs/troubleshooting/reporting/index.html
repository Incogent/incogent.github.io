Documentation / Troubleshooting

Report a problem

Send a reproducible report without exposing private data.

Based on 0.8.3-alpha.4 development documentation. Updated 2026-09-22. Some features may differ from your installed version.

Include the useful facts

  • What you were trying to do and what you expected.
  • The exact steps and selected Action/Workflow.
  • Blackbird version and relevant package, engine, or external-tool versions.
  • The exact error and whether it happens every time.
  • The relevant run log, after reviewing it for sensitive content.

Send the report

Use Report Issue from a failure result when available, or Send Feedback from the main window. Review the information and attachments before submitting. If the problem concerns an Action from another author, include its creator and package identity so the ownership is clear.

Avoid sending licenses, tokens, passwords, entire configuration directories, proprietary project files, or unrelated screenshots. Replace sensitive paths and names consistently so the report remains understandable. Keep an unmodified original log privately if support needs clarification.

Reproduce safely

Try a disposable project or input only when it can reproduce the same failure. Do not repeat a public upload, deployment, or deletion simply to create a recording. Tell support what you already tried so they do not ask you to repeat it unnecessarily.

For a startup problem with no History entry, provide the startup error and the point reached before it appeared. A photo or screenshot is useful for a visual defect; a copied error message is better for searchable diagnostic text.
