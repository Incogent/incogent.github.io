Projects, settings, and shared values

Understand where settings come from and why Actions can share them.

Based on 0.8.3-alpha.4 development documentation. Updated 2026-09-22. Some features may differ from your installed version.

Actions introduce settings

An Action declares the information it needs. Blackbird turns those declarations into settings controls, validates the entered values, and supplies the values when that Action runs. You do not need to edit JSON to configure an Action.

Some settings are deliberately shared. For example, Open Godot Project and Export Godot Build both use the same Godot project setting. Change that project's value once and subsequent runs of both Actions receive it.

Choose the right scope

ScopeWhere you edit itMeaning
ProjectProjects, or Configure ActionA separate value for each selected project
ApplicationSettings > Action Settings, or Configure ActionA value shared across this Blackbird installation
RunThe run or queue configuration promptA choice for that execution

Remembered run values are suggestions for a future prompt, not a replacement for persistent project settings. Secret run values are not remembered.

Configure an Action

  1. Select the intended project and device.
  2. Open the Action's menu and choose Configure Action, or follow the configuration prompt shown when a required setting is missing.
  3. Fill in the visible required fields. Some fields appear only after another selection makes them applicable.
  4. Save and run the Action. Review any run-specific choices before continuing.

Named options give one setting several named alternatives. Profiles select a group of related settings together, such as a build target and output directory. One available option/profile can resolve automatically; multiple alternatives require a choice.

What is shared, and what is not

Sharing is based on the setting's exact identity, not two controls having the same label. An Action-specific setting stays with that Action. A profile is owned by its Action and project; it is not a global variable store.

Queued items retain captured configuration. Changing a project setting does not silently rewrite values already saved into a queue item or Workflow. Edit and review that saved item when you intend to update it. Authors can learn the underlying identities in Sharing settings.
